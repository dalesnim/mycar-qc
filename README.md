# MyCar - контроль качества кузова

Страница для отметки дефектов кузова машины: кликаешь по карте кузова - появляется метка, заполняешь карточку дефекта, следишь за статусами в списке и сводке. Дефекты хранятся на сервере и переживают перезагрузку страницы и перезапуск сервера.

## Что умеет

- карта кузова из SVG, кликаешь по ней и появляется метка дефекта
- карточка дефекта: тип, зона, серьёзность, комментарий
- без типа и зоны дефект не сохранится, покажет ошибки
- список дефектов с фильтрами по типу и статусу, работает вместе с картой
- статусы: new -> in_repair -> resolved / rejected, назад вернуть нельзя
- сводка сколько дефектов в каком статусе
- сервер на Express, дефекты хранятся на нём а не в браузере
- всё сохраняется в `server/data.json`, перезапустил сервер - данные на месте
- отчёт PDI по кузову: таблица дефектов и итог годен / не годен к выдаче
- вход по логину и паролю (проверяет сервер), выход кнопкой
- роли: инспектор отмечает дефекты, мастер переводит статусы ремонта.
  Роль проверяется на сервере, чужое действие вернёт 403
- сводка показывает годен ли кузов к выдаче
- сервер пишет лог в `server/server.log` - по нему можно отследить запросы и ошибки

## Стек

Фронт: Vue 3 + TypeScript + Vite. Сервер: Node + Express. Тесты: Vitest.

## Структура

- `src/type.ts` - типы (Defect, Status, Severity)
- `src/store.ts` - состояние и запросы к API
- `src/validation.ts` - validateDefect
- `src/fsm.ts` - переходы статусов и canTransition
- `src/summary.ts` - подсчёт сводки
- `src/components/` - CarMap, DefectCard, DefectList, StatusSummary
- `src/__tests__/` - тесты фронта
- `server/` - API-сервер (app, db, rules, storage, report)
- `server/__tests__/` - тесты сервера

## Как запустить

Нужно два терминала: один для сервера, второй для фронта.

```sh
npm install
npm run server
```

и во втором терминале:

```sh
npm run dev
```




## API коротко

Сервер слушает http://localhost:3000. Роль передаётся заголовком `x-role`
(inspector или master), сервер проверяет её на каждом действии.

Тестовые пользователи: `inspector / 1234` и `master / 1234`.

- POST `/login` - вход, возвращает имя и роль (или 403)
- GET `/defects` - список дефектов (можно `?vin=` для одного кузова)
- POST `/defects` - создать дефект (только инспектор)
- PATCH `/defects/{id}` - изменить дефект; статус переводит только мастер и только по правилам FSM
- DELETE `/defects/{id}` - удалить (только инспектор)
- GET `/defect-types` - справочник типов дефектов
- GET `/inspections/{vin}/pdi-report` - отчёт PDI страницей

Если данные неправильные - 400 с текстом ошибки, нет прав - 403, не найдено - 404.

## Тесты и линтер

```sh
npm run test:unit
npm run lint
```

Тесты фронта: FSM, валидация, сводка. Тесты сервера: создание/изменение/удаление,
валидация, сохранение после перезапуска, отчёт PDI. Плюс флоу-тесты как себя ведут
разные пользователи: умный (всё по порядку), обычный (правильные данные но кривой
порядок действий) и тупой (null, пробелы, буквы вместо цифр - сервер отвечает
понятной ошибкой, а не падает).
